# Instalación base sin datos piloto · 9 de noviembre de 2026

`BaseSeeder` prepara el administrador inicial y los catálogos completos mediante una entrada explícita de consola. La implementación y la verificación manual en una base aislada están aprobadas; **el despliegue productivo de esta entrega está pendiente**.

## Alcance

Incluye territorios, la matriz vigente de cuatro roles y 52 permisos, catálogos forestales, taxonomía ampliada, condiciones, tipos de evidencia y mantenimiento y reglas de clasificación. `ExtendedTaxonomySeeder` reutiliza únicamente los catálogos del manifiesto versionado de Ornato: no requiere el libro ni el paquete privado de importación.

En una base vacía quedan 45 familias, 143 especies, 145 nombres comunes, 16 emplazamientos y 65 condiciones. El seeder crea solamente el administrador configurado: no crea cuentas de desarrollo adicionales, instituciones, inventarios piloto, árboles, inspecciones ni lotes importados. No elimina registros existentes.

`RiskMethodologySeeder` y `CarbonSpeciesReferenceSeeder` preparan referencias para las organizaciones que **ya existan**, manteniendo su separación institucional. No crean organizaciones y en una base sin ellas no generan parametrización institucional. No importan visitas ni recalculan árboles.

## Administrador inicial y configuración

`config/base_seed.php` lee `SYSFOREST_BASE_ADMIN_EMAIL`, `SYSFOREST_BASE_ADMIN_NAME` y `SYSFOREST_BASE_ADMIN_PASSWORD`. Los valores iniciales de correo y nombre están en `.env.example`; la contraseña de ese archivo permanece vacía. La clave real se configura por el canal privado autorizado, fuera de Git, de las imágenes y de la documentación. La base guarda su hash.

La excepción solicitada permite un mínimo de **10 caracteres exclusivamente para esta alta inicial por consola**, con mayúsculas, minúsculas, números y símbolos; máximo 128. La política web de **12 caracteres** sigue vigente. No hay contraseña predeterminada ni un mecanismo alternativo de autenticación.

Si el correo ya corresponde a un administrador activo, verificado, con `SUPER_ADMIN` nacional vigente y sin la clave general de desarrollo, se conserva: no cambian su contraseña, nombre, fecha de verificación, asignación ni fecha de concesión. Cambiar la variable de contraseña no la restablece. Una cuenta incompatible provoca un error; no se promueve, reactiva ni se le concede un rol automáticamente.

En local, completar las variables en el `.env` privado. En el servidor se usa `/opt/sysforest/private/production.env`, con permisos `0600`; el operador autorizado configura la clave sin imprimirla. `--env-file` suministra la configuración de Compose y `env_file` la inyecta en PHP: comprobar ambos cuando se adapte el procedimiento. Si hay configuración Laravel cacheada, ejecutar `config:clear` antes de sembrar **en el mismo contenedor** que recibe las variables actuales. Los procesos persistentes requieren recreación para cargar cambios de entorno; `restart` no renueva sus variables.

## Comando estándar

Con la imagen actual y la conexión migradora configurada:

```bash
php artisan migrate --seed --seeder=BaseSeeder --force
```

`--seed` habilita la siembra y `--seeder=BaseSeeder` selecciona la clase. No usar `--seed BaseSeeder`. El comando aplica migraciones pendientes y luego ejecuta la preparación base; no borra tablas. Los cambios del seeder se confirman juntos en una transacción y una incompatibilidad los revierte. Las migraciones ya aplicadas no se revierten si después falla la siembra.

Desde `/home/josev/SYSFOREST`, con los servicios de datos ya preparados, el inicializador local conserva la credencial migradora:

```bash
docker compose run --rm --no-deps init php artisan migrate --seed --seeder=BaseSeeder --force
```

Se sustituye el **comando** `sysforest-migrate` por `php artisan`; no se pasan opciones al script `docker/php/migrate.sh`, que ejecuta sus propios comandos y también atiende la base local de pruebas. No reemplazar el entrypoint de la imagen por PHP: ese entrypoint carga el secreto `DB_PASSWORD_FILE`.

Si hay una caché de configuración anterior, usar esta variante en una sola ejecución:

```bash
docker compose run --rm --no-deps init sh -c 'php artisan config:clear && php artisan migrate --seed --seeder=BaseSeeder --force'
```

En producción, desde el directorio de la versión activa bajo `/opt/sysforest/releases/`, después del respaldo y de construir la imagen que contiene esta entrega:

```bash
docker compose --env-file /opt/sysforest/private/production.env -f compose.production.yml \
  --profile maintenance run --rm --no-deps migrate \
  sh -c 'php artisan config:clear && php artisan migrate --seed --seeder=BaseSeeder --force'
```

El paquete desplegado no necesita una carpeta `.git`: debe contener el código, configuración, migraciones, seeders y sus manifiestos públicos versionados. Las dependencias PHP se instalan al construir la imagen; el entorno privado se conserva fuera del paquete. `DatabaseSeeder` y los seeders de desarrollo mantienen su flujo piloto anterior y no se usan para esta preparación productiva.

## Repetición y conflictos

`AuthorizationSeeder` **sincroniza la matriz exacta de permisos de los cuatro roles existentes**. Esto puede retirar permisos añadidos manualmente a esos roles; no debe describirse como una operación exclusivamente aditiva. No asigna roles adicionales a personas.

Los catálogos ampliados conservan códigos, nombres, padres, actividad, orden, descripciones y nombre principal existentes. Se reutilizan referencias compatibles; una referencia obligatoria ausente, inactiva o incompatible, o un nombre equivalente bajo otro código, detiene la transacción sin sobrescribirlo. No se inventan sinónimos ni se interpreta la taxonomía transcrita como una validación científica. Las huellas del manifiesto y de su fuente quedan fijadas en el servicio.

## Verificación realizada

La comprobación manual usó PHP 8.4 y PostgreSQL/PostGIS en un entorno temporal aislado, sin red externa ni datos operativos existentes:

- `migrate --seed --seeder=BaseSeeder --force` completó una instalación vacía.
- Repetir exactamente el comando conservó los conteos, el hash de contraseña y la asignación administrativa con sus fechas.
- Resultado: un usuario, cuatro roles, 52 permisos, 45 familias, 143 especies, 145 nombres comunes, 16 emplazamientos y 65 condiciones; cero organizaciones, inventarios, árboles, inspecciones e importaciones.
- La recreación con `migrate:fresh` y el mismo seeder también terminó en esa base desechable, incluidas las 25 funciones SQL con `CREATE OR REPLACE`. **No se usa `migrate:fresh` para actualizar producción.**
- Formato PSR-12, sintaxis PHP y revisión de cambios aprobados. No se crearon ni ejecutaron suites automatizadas.

Esta evidencia no acredita todavía la ejecución productiva, el ingreso desde navegador ni un envío de correo. El cierre del despliegue se registrará por separado cuando concluya.
